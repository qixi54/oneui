# OneUI v0.8.9 Release Plan

## Part 1 执行摘要

本计划用于把已完成的 DatabaseView/Kanban ergonomics 改动按 OneUI 标准发版链发布到 npm 主站。当前 `@oneflowui/ui` 主站最新版本是 `0.8.8`，仓库版本也仍为 `0.8.8`，因此必须先提升到 `0.8.9`，然后执行仓库内门禁、发包门禁、tarball 外部 consumer smoke 与实际 publish。

## Part 2 需求分析

P0：版本必须唯一，不能重发 `0.8.8`。P0：必须走 npm 主站而不是镜像站。P0：必须执行 `npm publish --dry-run`、`npm pack`、tarball 外部 consumer build smoke。P1：发布证据、proof 和 closeout 必须写回 FlowAPI。

## Part 3 详细方案

代码改动限制在版本号与 release 文档，不对功能实现做额外风险扩散。发版前执行 `npm run lint`、`npm run lint:style`、`npm test`、`npx vitest run src/tests/database-view.integration.spec.ts`、`npm run type-check`、`npm run build`。完成后使用 `npm publish --dry-run --access public --registry=https://registry.npmjs.org` 与 `npm pack`，扫描 `dist` 中 `worker / import.meta.url / assets` 风险，再用 `Vite 5.4.21` 和 latest stable Vite 进行 tarball consumer smoke。全部通过后执行真实 `npm publish --access public --registry=https://registry.npmjs.org`。

## Part 4 实现路线图

Phase A：冻结 release scope，版本提升到 `0.8.9`。Phase B：跑仓库内门禁。Phase C：跑发包门禁与外部 consumer smoke。Phase D：执行真实 publish，校验 `npm view @oneflowui/ui version`，写回 proof 与 FlowAPI closeout。

## Part 5 风险评估

高风险一：默认 registry 仍指向镜像站，导致 `whoami` 与 `publish` 站点错配；缓解动作是所有 publish 相关命令显式指定 `https://registry.npmjs.org`。高风险二：tarball 虽能打包但 consumer 侧构建失败；缓解动作是在两个 Vite 版本矩阵下做真实 install + build。中风险：当前工作区含其他已存在改动；缓解动作是仅提升版本与补文档，不回滚或覆盖现有用户改动。

## Part 6 验收标准

1. `package.json` 与 `package-lock.json` 版本提升到 `0.8.9`。
2. `npm run lint`、`npm run lint:style`、`npm test`、`npx vitest run src/tests/database-view.integration.spec.ts`、`npm run type-check`、`npm run build` 全部通过。
3. `npm publish --dry-run --access public --registry=https://registry.npmjs.org` 与 `npm pack` 通过。
4. tarball 在 `Vite 5.4.21` 与 latest stable Vite consumer 中均能成功 `vite build`。
5. `npm publish --access public --registry=https://registry.npmjs.org` 成功，且 `npm view @oneflowui/ui version --registry=https://registry.npmjs.org` 返回 `0.8.9`。

## Part 7 回滚方案

若在真实发布前任一门禁失败，则停止 publish，仅保留本地版本与 proof 变更，修复后重跑。若真实发布成功，则不回退已发布版本，而是通过后续 patch 版本修复。
